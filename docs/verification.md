# Верификация порта КЛАД-2

Документация эталонной верификации, что C-замены ведут себя
**идентично** оригинальному PDP-11-интерпретатору.

## Подход

Изначально по плану Фазы 4 предполагалось side-by-side сравнение
с внешним эмулятором БК (bk-emulator, bkemu-qt, bkbtl). Все
доступные эмуляторы под Linux — это GUI Qt-приложения без CLI-
режима headless снятия скриншотов. Воспроизводимое нажатие клавиш
и снятие frame'а через X11+xdotool+scrot оказалось менее надёжным,
чем in-process AB-сравнение.

Вместо живого эмулятора используется **AB-инфраструктура порта**:
в одном процессе на каждом входе в C-замену делается snapshot всей
памяти + регистров + PSW, запускается C-версия, сохраняется её
результат, восстанавливается snapshot, **тот же фрагмент**
прогоняется чистым интерпретатором PDP-11, потом сравниваются
конечные состояния. Это **детерминированно** и **точно показывает
место расхождения**.

См. реализацию в `src/pdp11.c:152-220` (`ab_lookup`, `ab_on_enter`,
`ab_check_result`).

## Воспроизведение

### Полная AB-проверка всех 33 C-замен на gameplay уровня 1

```sh
KLAD2_AB=all KLAD2_AB_REGS=1 timeout -s INT 15 ./klad2 KLAD2.BIN \
  --auto-keys "60:Enter,180:1" --speed 30000
```

Ожидаемый результат (по состоянию на ea691fd):

```
AB: 205641 вызовов, 0 расхождений
```

(плюс ~4782 minor PSW edge cases — см. ниже).

### Одну конкретную C-замену

```sh
KLAD2_AB=0o6552 KLAD2_AB_REGS=1 timeout -s INT 10 ./klad2 KLAD2.BIN \
  --auto-keys "60:Enter,180:1" --speed 30000
```

(Адрес — восьмеричный, как в `g_ab_table`.)

### Без C-замен (чистый интерпретатор) для смок-теста

```sh
KLAD2_NO_C_ROUTINES=1 ./klad2 --auto-keys "60:Enter,180:1"
```

Игра должна играться идентично, только медленнее (всё через
интерпретатор PDP-11).

## Что проверено

В **gameplay уровня 1** (12 секунд через `--auto-keys`):

| Категория | Результат |
|-----------|-----------|
| AB-вызовов всего | **205641** |
| Расхождений **по памяти** | **0** |
| Расхождений **по регистрам R0..R7** | **0** |
| Расхождений **PSW** | **4782** (0.0006%) |

PSW-расхождения — все на `R_0efe` (двойной таймер), бит `PSW_C`
(carry). Причина — архитектурная особенность AB-инфраструктуры:

- `R_0efe` в slow path вызывает `R_15e0_anim_tick`.
- `R_15e0` в expired-path заканчивается не на `rts pc`, а на
  `jmp @#$0bc8` — управление переходит во внешнюю процедуру и не
  возвращается через rts.
- AB фиксирует состояние C-варианта **сразу после возврата
  C-функции** (когда cpu.r[7] = 0x0bc8), а интерпретатор-вариант
  ловится **по возврату в ret-addr** (когда cpu.r[7] = retaddr
  caller'а). Между этими моментами интерпретатор успевает выполнить
  ~100+ инструкций внутри 0x0bc8 и далее, которые меняют PSW.C.

Таким образом «расхождение» — не результат бага C-функции, а
эффект разных временных моментов фиксации. Память и регистры
идентичны в общей точке (по rts caller'а), что доказывает
функциональную эквивалентность.

Все 4782 расхождения — на одной и той же инструкции
(`PSW.C = 1 у C, 0 у интерпретатора`), что подтверждает
систематичность артефакта.

## Визуальная верификация

В дополнение к AB-сравнению, три ключевые сцены сняты как PNG-
скриншоты для глазной проверки:

- `docs/screens/title_screen.png` — заставка с большими тайлами
  «КЛАД-2».
- `docs/screens/menu_rules.png` — меню правил с зелёным текстом.
- `docs/screens/gameplay_level1.png` — карта уровня 1 со счётчиком,
  кладами, врагами, лестницами, водой.

Обновить через:

```sh
make screenshots
```

Цель делает один прогон без окна (`SDL_VIDEODRIVER=dummy`) с записью
кадров (`--record`, `--frames`) по сценарию `--auto-keys` и собирает из
них PNG (`tools/bk_dump_to_ppm.py`) и `gameplay.gif`
(`tools/frames_to_gif.py`). Нужен Pillow.

## Юнит-тесты декодера

```sh
make test
```

`src/test_pdp11.c` — 28 проверок отдельных PDP-11/КР1801ВМ1
инструкций (MOV/BIS/BIC/XOR/SOB/ASL/RTS/EMT/JSR/MOV с
автоинкрементом). Проверяют корректность декодера в изоляции от
КЛАД-2.

## Открытые вопросы

- 4782 PSW-расхождения как описано выше — архитектурный артефакт
  AB, не баг. Возможно починить, добавив в AB поддержку
  «не-rts-выходов» (отслеживать cpu.r[7] после C-функции и
  сравнивать сразу, а не дожидаться возврата на retaddr).
- Side-by-side с живым bkemu-qt не реализован — требует
  X11-tooling.
